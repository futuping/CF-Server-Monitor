# 私有管理监控接入

2026-10-22 本地候选。部署状态须以实际 Worker 版本、权限及读回结果为准。

在保留原公开节点的前提下，新增节点可以从首次写入数据库就设置 `is_hidden: "1"`，只向管理端同步资源和历史。公开 REST 与 WebSocket 均复核数据库中的当前可见性；旧休眠连接没有新增权限字段时按公开连接处理。订阅消息不能改变握手时确认的管理员权限。

此接入不使用管理员 JWT，不赋予代理、远程命令、配置写入、上报或数据库管理权限，不改 Agent 采集、上报密钥、原通知或公开主题。

## Worker 配置

以下配置缺失或格式错误时，私有接口返回 503：

| 名称 | 内容 |
| --- | --- |
| `MONITOR_READ_TOKEN` | 独立随机 Bearer token，32–256 个 base64url 字符；建议 32 字节随机数编码，不复用 Agent 或管理员凭据。以 Worker secret 保存。 |
| `MONITOR_READ_SERVER_IDS` | 允许同步的服务器 UUID，逗号分隔，最多 100 项；仅包括要接入管理端的在用主机。 |
| `MONITOR_READ_SOURCE_IPS` | 管理端同步主机的精确公网 IPv4/IPv6，逗号分隔，最多 8 项，不接受网段或通配符。 |

服务使用 Cloudflare 边缘覆写的 `CF-Connecting-IP` 校验来源，不信任 `X-Forwarded-For`。若请求被站点原有安全规则拒绝，应由所有者在安全规则中对该来源及下面两个 GET 路径配置所需的精确例外；不更换 User-Agent 或绕过验证。

管理端把 token 写入独立 0600 文件，仅由服务读取；不要传给浏览器、写入 URL、提交到 Git，或在日志中打印请求头。

## 固定只读接口

请求头必须是 `Authorization: Bearer <独立token>`。管理员 JWT、登录 Cookie、查询字符串中的 token 都不能代替该凭据。来源不匹配返回 403，凭据不匹配返回 401。

| 路径 | 参数 | 返回 |
| --- | --- | --- |
| `GET /api/monitor/servers` | 不接受参数 | 与 `/api/servers` 相同形状，只含配置白名单中的服务器，包含隐藏服务器。 |
| `GET /api/monitor/history?id=<UUID>&hours=1` | `id` 必须在白名单，`hours` 只能为 `1` 或 `24` | 与 `/api/history/all` 相同形状的实际历史点数组。 |

其他方法、Upgrade、未知或重复参数被拒绝。不开放跨域读权限，响应为 `Cache-Control: private, no-store`。接口沿用原资源与历史单位：内存和磁盘 MiB、时间戳毫秒；TCP 超时、未配置探测和缺失样本保持原语义。实际 IP 继续掩码为 `"1"` / `"0"`，备注、自动更新字段等沿用原投影的剔除规则。授权范围不包括暂停、退役或其他未列入的主机。

## 发布与验证

1. 保存当前 Worker 版本、绑定、域名、变量、secret 名称和相关 D1 对象的私有快照；保留原运行配置，不从示例 `wrangler.toml` 重建生产绑定。
2. 先发布完整候选但不配置 `MONITOR_READ_*`。确认公开节点、公开统计、原报告和通知保持，私有路径返回 503。记录这一版为包含隐私保护的回退基线。
3. 配置独立 token、白名单和同步来源。验证无凭据 401、错误来源 403、正确来源及 token 200；未知节点、重复参数、超过 24 小时和写方法不能取得数据。
4. 使用原 `import_servers` 管理操作一次导入需要新增的记录，每条记录在同一 `INSERT` 中带 `is_hidden: "1"`。不要先以普通新增公开后再编辑隐藏。读取导入结果及所有新增行，确认旧 UUID、排序、启停、历史分区及原配置未改。此候选还修正了原导入语句 37 列配 38 占位符导致全部跳过的问题。
5. 仅安装本次新增的探针单元，验证原 Agent secret 的真实上报、公开列表与详情/历史仍不可见，以及匿名 all/single WebSocket 不能收到隐藏样本。管理端验证新鲜资源、1 小时/24 小时真实历史及原流量计量、通知、执行器和代理保护项。

新增私有数据后，不能回到缺少 WebSocket 隔离的旧程序。管理端页面或同步服务可独立回退，CF 保留上述隐私保护基线；若撤销私有接入，先撤销 token 并停止同步，不清空既有计量、历史或通知队列。后续合并上游更新时保留这些隔离约束并重跑回归。

新增行只接资源与延迟时，使用 `offline_notify_disabled: "1"`、`traffic_alert_percent: 0`、空流量额度及到期日、`auto_renewal: "0"`，避免增加 CF 的离线、月量及到期通知；原 Exchange 通知维持独立。`offline_notify_disabled` 不控制资源规则。若原资源规则用空 `servers` 表示全部节点，应在新增前仅把该规则目标固化为原节点集合，保持其 ID、门槛、状态及其他字段，避免自动把新节点纳入；原规则为空时不需修改。

新增行使用 `collect_interval: 0`、`report_interval: 60`、`wss_report_interval: 2`、`connection_mode: "auto"`、`ping_mode: "tcp"`、`auto_update: "0"`；当前 Agent 配置协议把 collect 0 解析为 2 秒。延迟字段留空继承已有全局目标，不增加目标或提高周期。不要伪填价格、套餐或历史分区。

## 后续更新保护

上游每日自动同步及手动触发保持启用。同步工作流使用普通 `git fetch` 和 `git merge upstream/main` 保留本地提交，不执行 reset 或强制推送；先用 `npm ci` 安装锁定依赖，再显式运行隐私边界专项和完整回归，通过后才普通推送 `main`。合并冲突、边界检查失败或远端并发更新导致推送失败时，工作流停止，不覆盖原生产分支。

Cloudflare Builds 使用的 `npm run build:frontend` 会先执行 `prebuild:frontend` 隐私专项。原 GitHub 部署工作流也改用 `npm ci` 并在构建、发布前执行完整回归；生成的 Wrangler 配置设置 `keep_vars = true`，保留后台配置的私有白名单和来源变量。Worker 名称、主题、原 secret、绑定及定时任务均不在此项修改范围。这些更新保护必须随隔离代码保存在实际构建分支；只在控制台上传一次程序不能替代源码持久化。

以上仅涉及 CF 探针维护分支和部署检查，不修改 PPanel 官方程序及其直接升级路径。

## 验证与性能边界

在项目锁定的 Nix Node.js 22 环境运行：

```sh
nix develop --command npm run test:all
nix develop --command npm run build:frontend
```

新增专项覆盖真实 D1 的白名单、资源与历史契约、独立只读身份、来源限制、匿名 REST 缓存隔离、隐藏后旧连接、休眠连接、订阅消息提权、排队后隐藏、查询失败关闭公开发送、隐藏探针继续上报，以及导入新增行不覆盖原对象。原有 Agent 参数、历史抽样、OAuth、通知和前端行为测试继续保留。

可见性不使用元数据的 120 秒缓存。仅当某个广播批次确实匹配公开订阅时查询一次可见 ID 列表，按最多 90 个 ID 分片，由同批全部公开接收者复用；没有匹配公开订阅时不新增查询。该选择避免隐藏修改后的缓存窗口，但公开页面持续打开时会增加 D1 只读查询。这里不声称完成公网负载、免费额度余量或长期运行验收。
